# Public exposure threat inventory (av12)

Assumption: an anonymous remote caller can reach every HTTP route. Indexed records and identity/OAuth metadata are remote input. This inventory is the pre-change assessment; each fix below must have an offline regression test that fails before the corresponding implementation change.

## HTTP routes

| Route | Anonymous caller can cause | Worst case | Fix and regression test |
| --- | --- | --- | --- |
| `GET /healthz` (new container probe) | Repeated cheap health checks | Request/log/resource flood | Constant response, no details; standard global request bounds and headers; test status/body and headers. |
| `GET /xrpc/_health` | Repeated cheap health checks | Request/log/resource flood | Same global bounds and headers; test status/body and headers. |
| `GET /.well-known/did.json` | Read configured app DID/service endpoint | Invalid config can publish a misleading endpoint | Validate DID and public origin configuration; test valid and rejected config. |
| `GET /.well-known/oauth-client-metadata.json` | Read public OAuth client metadata | Metadata can advertise an unsafe client/redirect if configuration is malformed | Validate HTTPS public origin and metadata URLs; test metadata and invalid origin. |
| `GET /login` | Fetch static login form | Request flood | Global limits and security headers; test headers. |
| `POST /oauth/authorize` | Submit arbitrary handles/DIDs and initiate identity plus OAuth discovery/PAR requests | SSRF, slow/large upstream responses, repeated login work, request-body allocation, authorization redirect injection | Shared guarded outbound transport; body cap; per-IP and global login/fetch limits; strict callback/redirect validation; tests cover forbidden/rebinding addresses, oversized body, 11th attempt/429, and unsafe redirect. |
| `GET /oauth/callback` | Submit code/state/issuer values; with a valid short-lived browser binding, complete a pending token exchange | OAuth endpoint SSRF, token exchange/revocation abuse, oversized query, information leak | Guard all OAuth discovery/JWKS/PAR/token/revocation requests, enforce callback/state/PKCE/DPoP checks and bounded query/upstream data; generic errors; tests for state/nonce/issuer and safe errors. |
| `POST /logout` | Without a session, trigger cookie clearing; with a session, revoke tokens and unregister the account | CSRF or repeated token-revocation work | Preserve same-origin check, bounded body, rate limit, session invalidation and remote revocation through the guard; test CSRF and logout revocation. |
| `GET /app` | Read a local user timeline and progress | Large DB reads, repeated profile-wide scans, unbounded crafted input, stored XSS in remote records | Indexed bounded queries, capped page size and record text/fields, HTML escaping, secure headers/CSP; test huge limit, hostile display/text/embed data and scan bounds. |
| `GET /notifications` | Read local notification page | Whole-record scans, many rows, hostile stored strings | Indexed limited query, capped page size and output fields, HTML escaping and headers; test maximum limit and hostile notification. |
| `GET /profile` | Read a profile, posts, and relationship counts for a caller-supplied DID | Whole-DB scans, arbitrary DID handle-refresh queue growth, reflected/stored XSS | Look up only tracked/indexed DIDs; bounded indexed queries and pagination; escape all fields and URLs; test arbitrary DID does not enqueue work, huge limit, hostile profile/post. |
| `GET /thread` | Read a post thread at caller-selected depth and parent height | Recursive reply fan-out / CPU and memory exhaustion; whole scans; hostile records | Hard depth/parent/reply budgets and indexed `LIMIT`; test extreme depth plus a large reply set and verify bounded result/work. |
| `POST /post` | Authenticated user asks OAuth/PDS to write arbitrary text | CSRF, oversized body, excessive upstream writes, token/error leakage | Origin + fetch-metadata CSRF checks, body/field cap, per-IP/global write limits, guarded PDS request and sanitized error; tests for cross-origin, size, limits and redacted errors. |
| `POST /like` | Authenticated user asks PDS to create/delete a like for supplied URI/CID | CSRF, malformed/unbounded input, repeated upstream writes | CSRF/body/rate limits, strict URI/CID validation, guarded PDS request, generic errors; tests for each. |
| `POST /repost` | Authenticated user asks PDS to repost supplied URI/CID | CSRF, malformed/unbounded input, repeated upstream writes | CSRF/body/rate limits, strict URI/CID validation, guarded PDS request, generic errors; tests for each. |
| `GET /xrpc/app.bsky.actor.getProfile` | Read profile for arbitrary actor; missing profile currently asks the background worker to refresh its handle | Arbitrary DID queue growth and repeated whole-DB counts | Only queue refreshes for tracked/indexed DIDs; indexed bounded profile aggregates; rate limit; test arbitrary DID causes no queued fetch. |
| `GET /xrpc/app.bsky.actor.getProfiles` | Request up to 25 actors | Up to 25 repeated whole-DB scans and response amplification | Cap request/response and use indexed batch queries; test large/repeated actors and bounded storage calls. |
| `GET /xrpc/app.bsky.feed.getAuthorFeed` | Read a paginated author feed | Per-record profile and interaction scans; caller-controlled page size | Indexed query plan and hard page cap; test `limit=1000000` returns at most cap and a large fixture stays within query budget. |
| `GET /xrpc/app.bsky.feed.getPosts` | Request repeated URIs | Whole DB materialization followed by per-URI scans | Batch indexed URI lookup and cap URI count/length; test cap and bounded storage call. |
| `GET /xrpc/app.bsky.feed.getPostThread` | Request nested thread with caller-selected depths | Exponential reply tree and large response | Hard traversal/reply budget plus indexed limit; test extreme depth/fan-out remains bounded. |
| `GET /xrpc/app.bsky.feed.getTimeline` | With a service JWT, read user's local timeline; JWT verification can fetch issuer DID document | DID-document SSRF; scans and large response | Guard issuer DID fetch; indexed bounded timeline; per-IP/global fetch/API limits; test JWT lookup guard and page cap. |
| `GET /xrpc/app.bsky.feed.getLikes` | Read all interactions for a URI before taking the requested page size | Whole DB scan and unbounded repeated work | Indexed URI/collection lookup, cursor/limit cap; test limit cap and index-backed bounded query. |
| `GET /xrpc/app.bsky.feed.getRepostedBy` | Same as likes for reposts | Whole DB scan and repeated work | Indexed lookup and cap; test bounds. |
| `GET /xrpc/app.bsky.graph.getFollows` | Read follows and profiles for an actor | Whole DB scan plus per-profile scans | Indexed bounded follows query and batched profiles; test page cap/query bound. |
| `GET /xrpc/app.bsky.graph.getFollowers` | Read followers for an actor | Whole DB scan plus per-profile scans | Indexed bounded followers query and batched profiles; test page cap/query bound. |
| `GET /xrpc/app.bsky.notification.listNotifications` | With a service JWT, read a page; JWT verification can fetch issuer DID document | SSRF during issuer lookup, large result/scan | Guard issuer DID fetch, indexed cursor query, page cap and rate limits; test. |
| `GET /xrpc/app.bsky.notification.getUnreadCount` | With a service JWT, count notices; JWT verification can fetch issuer DID document | SSRF during issuer lookup and expensive count | Guard issuer DID fetch and maintain/index a bounded count query; test. |

There is no search route in this version. Search-specific rate limiting is therefore not applicable until search exists.

## Outbound network paths

| Path and source | Attacker-controlled value | Worst case | Fix and regression test |
| --- | --- | --- | --- |
| PLC DID document GET (`HttpIdentityBackend`) | DID from login, JWT issuer, or remote record | SSRF to loopback/private/tailnet/link-local/metadata; redirect or DNS rebinding; slow/huge body | One guarded HTTP transport: HTTPS except explicitly configured local test hosts, resolve and reject every forbidden IP, pin socket to checked address, recheck each redirect, cap hops/body/time; fake-resolver tests for every prohibited range, public IP, redirect and rebinding. |
| `did:web` document GET | DID host from login/remote data | Same SSRF and response exhaustion | Same guard and tests; strict `did:web` host parsing. |
| Handle DNS-over-HTTPS and `/.well-known/atproto-did` GETs | Login handle or remote DID alias | SSRF via handle host, redirect/rebinding, response exhaustion | Same guard, validate normalized DNS name and HTTPS; fake-resolver and redirect tests. |
| OAuth resolver calls (handle/DID discovery, protected-resource and authorization-server metadata, JWKS, PAR, token, refresh, revoke) | User login and endpoints/keys from DID and OAuth metadata | SSRF to internal services, credential/code/token exfiltration, unbounded response or redirect | Make OAuth use the guarded transport for every call; allow only HTTPS except explicit test origins; bounded requests/responses and redirects; fake OAuth endpoints and transport tests. |
| OAuth session-backed PDS reads and create/delete-record writes via Atrium Agent | PDS service endpoint from DID/OAuth session | SSRF with user-bound access token; write amplification; unbounded response | Route all Agent traffic through the same guard with destination policy, pinned IPs, strict caps/timeouts; tests ensure public fake PDS succeeds and private/rebound target is blocked. |
| Backfill `getRepo` CAR (`HttpRepoSource`) | PDS endpoint in DID document; requested DID from queued follow/backfill | SSRF, redirect to internal hosts, 512 MiB memory per response, 120-second stall, global disk/CPU exhaustion | Use the shared guard, smaller explicit byte/time/concurrency limits, bounded global follow-only queue; fake resolver/redirect/oversize/timeout tests. |
| Jetstream WebSocket consumer | Configured URL (operator-controlled, not HTTP input) | Unsafe config may connect to an internal service; remote event size/volume can exhaust memory/CPU/storage | Validate secure `wss` outside explicit test hosts; cap frame/event sizes and ingestion rate; document operator trust; tests for URL/frame bounds. |
| Browser-loaded avatar/banner/post-image URLs (`cdn.bsky.app`) | DID/CID from indexed remote records | Client tracking/mixed-content or malformed attribute URL; does not make a server-side request | Construct fixed-origin HTTPS URLs from validated DID/CID segments, set CSP `img-src` allowlist; hostile-segment test. |

## Cross-cutting controls and proof

1. Centralize every server-side HTTP request above; no other `reqwest`/`hyper` client construction or direct fetch path remains. Verify with a source grep and transport-level tests.
2. Bound every public request: body bytes, URL/query dimensions, records/rows returned, thread traversal, outbound concurrency, per-IP and global request rates for login, writes, and fetch-triggering calls. Add indexes and replace every request-reachable whole-table record scan. A `limit=1000000` test must demonstrate the hard cap; the eleventh login attempt from one IP in a minute must return 429.
3. Preserve HttpOnly/SameSite=Lax cookies; set Secure for HTTPS public URLs. Keep same-origin CSRF checks on every state-changing POST, ensure a fresh random session ID after callback, maintain OAuth state/PKCE/DPoP nonce checks, protect key/session files at rest, and revoke remote OAuth tokens on logout. Confidential public-client keys must come from a secret file/env, never the repository.
4. Escape every remote string in HTML text and attributes. Accept only `http`/`https` external link facets and apply `rel="nofollow noopener noreferrer ugc"`. Add CSP without inline script, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`, and HSTS only when the public URL is HTTPS. Tests cover script payloads, `javascript:` links, oversized values and response headers.
5. Return generic errors and log neither tokens nor secrets/internal paths. Tests inject upstream/storage errors and assert no stack trace, token, or filesystem path appears in body/log capture.
6. Container deliverable: multi-stage Dockerfile, slim/static runtime, non-root identity, read-only root-compatible data volume, env/secret-file config, configurable bind, `/healthz` check, README instructions. Build and run locally if a container engine exists; never push or create cloud resources.
